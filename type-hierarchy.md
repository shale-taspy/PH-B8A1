In TypeScript's type hierarchy, unknown is the type-safe top type since any type can be assigned to it, whereas never is the bottom type because it is assignable to all types but accepts no values. Any completely skips the type system, acting as both a top and bottom escape hatch to deactivate compile-time checks.

Unknown is always preferred over any because it maintains type safety across borders, such as JSON.parse or external APIs. While any allows you to access properties or invoke methods without checks, which frequently results in silent runtime crashes, unknown prevents dangerous activities until you explicitly narrow its type using typeof, instanceof, or type guards. By demanding verification before use, unknown ensures that your code is tightly typed, detects errors early in development, and makes refactoring considerably safer across huge code bases. Using unknown also indicates that a value's actual shape is unclear rather than ignored, which encourages simpler handling of edge circumstances and reduces unexpected bugs in production throughout your application's lifetime.
